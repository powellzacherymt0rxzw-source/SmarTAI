# G07 当前任务信息与 BYOK 门禁纠正阶段（2026-07-26）

## 1. 阶段目标

本阶段只修复新建任务到题目上传之间的三个断点，不扩成长页面：

1. 创建任务后仍能回到同一份 Figma 03 表单，修改当前任务的名称、固定学期、课程和标签。
2. 新建多选标签成功后关闭候选弹层，不要求教师额外点击空白处。
3. Figma 04 的“开始识别题目”在没有可用模型时保持灰态，但点击和悬浮都能解释原因，并提供真实 BYOK 恢复入口。

视觉继续以 `03 New Task 新建任务.png` 和 `04 Add Problems 添加题目文件.png` 为准：1300px 页面版心、900px 主工作区、单层圆角卡片、40/44px 控件和克制主蓝；没有恢复旧版资料配置长页。

## 2. 路由与交互决定

- 新增 canonical 编辑路由：`/tasks/:taskId/edit?returnTo=...`。
- 编辑页复用同一份 `NewTaskPage` 和 Figma 03 表单，不维护第二套字段或保存逻辑。
- Q01 标题右侧使用“编辑任务信息”入口；返回时保留上传页的文件对象、资料库选择、结构模式、提取说明和保存到资料库选项。
- 编辑保存使用既有 `PUT /tasks/:taskId`，成功后回到调用页；直接打开编辑路由时默认回到该任务的 Q01。
- `returnTo` 只允许当前任务路径、工作台或历史任务，拒绝站外和其他任务路径。
- 无模型时主按钮不是无解释的原生禁用控件：视觉保持灰态，悬浮 `title` 解释，点击打开可访问对话框；对话框的 BYOK 链接继续携带 Q01 草稿。
- 文件/来源缺失、加载中、请求处理中等其他门禁继续使用真正的 disabled，不把所有错误都改成可点击假按钮。

## 3. 后端与数据边界

- `UpdateTaskRequest.name` 现在限制为最多 200 字符；服务端统一去除首尾空白并拒绝纯空白名称。
- 学期、课程和标签仍使用既有 owner-scoped 校验；不能把其他教师的课程或标签写入当前任务，也不能修改其他教师的任务。
- React Query 更新成功后不再用 `TaskLite` 覆盖完整 `Task` detail cache，避免意外丢失 `problem_data / student_data`；改为失效并重新读取。
- Task/Course/Tag/BYOK 仍为进程内存存储。本阶段没有把它们描述成已持久化，也没有读取、记录或返回 key 原文。
