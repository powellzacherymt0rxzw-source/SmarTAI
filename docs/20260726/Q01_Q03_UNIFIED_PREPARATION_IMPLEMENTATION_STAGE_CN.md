# Q01–Q03 统一题目资料准备与连续审核阶段记录（2026-07-26）

> 状态：代码、定向回归与本地浏览器验收完成，等待用户视觉确认。
>
> 工作分支：`codex/figma-first-frontend-redesign`

## 1. 本阶段采用的最终产品决定

- 顶部流程最终改为八步：`新建任务 → 上传题目 → 审核题目 → 上传作答 → 校对作答 → 执行批改 → 复核批改 → 结果分析`。批改设置归入第 6 步，不再占一个额外顶层编号。
- 当前步骤与之前步骤的数字和文字均可点击返回；未来步骤保持不可点击。进入“新建任务”编辑当前任务时，不再额外放一个重复返回按钮。
- “上传题目”页同时承载题目、标答、评分标准、编程题测试资料四类来源。题目必填，其余可选；每一份来源独立选择上传/课程资料库、已按题整理/从原文提取和提取说明；评分标准还可直接使用自然语言描述。
- 页面只有一个主动作“识别并准备题目资料”：一次处理所有来源，并在同一后台任务里生成未上传的标答/评分标准；上传的最终答案也补成可审核步骤。
- 风险总览不再把正常 AI 生成内容显示成“缺失”，只列低置信、来源冲突、解析异常和生成失败；删除“批量导入资料”和“AI 补全缺失项”两个旧主入口。
- 审核页不再分“全部/单题”或题干/标答/评分标准 tabs。左侧为可滚动题号目录，右侧连续展示全部题目；每题完整显示题干、标答、步骤对应评分标准，只有编程题显示测试样例。各字段独立编辑，浏览态渲染 Markdown/LaTeX，编辑态显示原始源码。

## 2. 页面与交互实现

### Q01 `/tasks/:id/upload/problems`

- 四类资料位可用顶部角色切换和左右箭头浏览；每类允许增加/移除多个独立来源。
- 每个资料位独立执行 owner-scoped 预检；资料库来源使用独立 query，不会让第二份来源错误复用第一份结果。
- 0/0 模型时主按钮保持视觉灰态但可点击，弹窗说明 BYOK 缺口并提供携带草稿的真实入口。
- 空白的可选资料位不参与启动门禁和预检；教师从 BYOK 返回后，即使标答、评分标准或测试样例仍为空，也可直接开始统一准备。
- 题目来源为空时主按钮同样保持可点击的提示态：悬浮说明“至少添加一份题目来源”，点击弹窗列出缺少的题目/BYOK 条件并提供对应入口；只有请求进行中、模型配置读取中或读取失败时才原生禁用。
- 从步骤 1 返回任务编辑再回来，文件对象、资料库选择、来源模式、说明和当前资料位均保留。
- 评分标准资料位新增真实 `inline_text` 来源，不伪装成上传文件；可选“按题描述/整体规则”，前端与后端共同限制为 12,000 字，统一 Job 将其与标答步骤对齐后再进入审核。
- 单来源桌面布局只收紧外层间距、资料卡 padding、上传区高度和角色栏高度，不缩小正文或按钮热区；在 `1920×1080` 下标题、步骤条、单文件卡和主操作完整落在首屏内，`1280×720` 等小视口继续正常滚动而不挤压内容。

### Q03 `/tasks/:id/questions`

- Figma 14 式四张大指标卡置于首屏，搜索框独占一行，完整题目资料矩阵紧随其后。即使没有开放风险，矩阵仍列出每道题，并以绿色“已识别/已生成”表达正常题目、标答与评分标准；非编程题的测试资料显示为中性的“不适用”。
- 搜索处理 IME composition，避免中文输入过程混入多余英文或删除连带字符。
- 搜索保留可解释题目别名，例如“积分/积分题”可命中含积分公式的题目；表头直接点击排序，再点反向，题型列提供多选筛选。风险只覆盖对应状态单元格与审核提示，不再决定整行是否出现。

### 连续审核 `/tasks/:id/questions/:questionId`

- 左侧 96px sticky 题号栏独立滚动，显示每题 open risk 数并与正文滚动同步高亮。
- 上一题/下一题只是滚动定位，不建立第二套页面模式；搜索后的题号栏和正文使用同一结果集。
- 每题卡片按 `题目 → 标答/解题步骤 → 评分标准` 排列；评分标准与解答并排便于逐步核对。编程题另显示示例正确代码和 OJ 测试区，非编程题的 DOM 与文案均不出现测试样例。
- 测试样例按 example/hidden、stdin/function、输入、期望输出、解释和用途展示，各例可独立编辑。
- 页面底部一次确认全部；保留字段级“修改/保存”，修改题干、标答、评分标准或测试资料只解除对应风险。

### 作答连续校对 `/tasks/:id/students/:studentId?question=:questionId`

- 保留既有深链作为初始题目锚点，但取消“单学生×单题”页面模式：当前学生的全部题目始终连续渲染并可上下滚动。
- 左侧题号目录与 Q03 连续审核共用同一交互：固定在工作区内、可独立滚动、显示识别状态并与正文滚动同步；每题卡片保留题干、识别作答、识别提示、保存和上一题/下一题定位。
- 学生选择与题目筛选继续是两个独立维度。Safari 候选项在 `mousedown` 阶段阻止输入框先失焦，避免候选被卸载后点击失效；切换学生保留当前题目锚点。
- 两个搜索框使用本地 draft 和 composition 门禁；中文选词期间不改写 URL，选词结束后再同步，避免裸拼音、重复字符和联动删除。
- 校对作答、复核批改和结果学生详情的当前学生统一以较大加粗的 `学号 · 姓名` 单行展示；相邻学生仍是次级导航，搜索框相应收窄但保留可用宽度。

## 6. 2026-07-27 启动门禁回归修复

- 根因：旧判断把页面中尚未填写的可选资料行也视为阻塞项。没有 BYOK 时，BYOK 提示优先掩盖了该问题；配置 BYOK 返回后，阻塞理由切换成“存在空资料行”，主按钮因此变成不可点击。
- 修复：启动时只收集和预检真正配置过的来源；题目仍为唯一必填来源，标答、评分标准和测试样例的空白草稿行会被安全忽略。
- 交互：题目或 BYOK 缺失均使用同一“开始前还需要完成 N 项”弹窗；按钮保留 `title` 悬浮说明和帮助光标，弹窗提供“上传题目”与“前往 BYOK”的恢复动作。
- 原场景验证：Safari 中任务已有题目、模型从 0/0 变为 1/1、可选资料仍为空时，“识别并准备题目资料”恢复为可点击；没有触发真实识别调用。
- 空题目验证：隔离浏览器任务在 1/1 模型、题目为 0 时，按钮可点击且悬浮说明为“至少添加一份题目来源”；点击后弹窗准确显示 1 个缺口，“上传题目”关闭弹窗并回到题目资料位。
- 工程证据：visible-scope audit 扫描 69 个文件，TypeScript 与 Vite production build 通过（`929 modules transformed`）；浏览器控制台 `0 errors / 0 warnings`。
