## 1. R1 怎么实施

R1 不采用“先搭完所有页面空框架”，也不采用“一个页面写到底再发现共用结构不一致”。采用以下混合顺序：

1. 只搭首批页面共同需要的 token、顶部导航、版心、i18n 和基础响应式壳。
2. 先完成 `工作台 / Workspace` 这一条真实纵向切片，连接真实任务与模型状态并截图验收。
3. 再完成 `历史任务 / History`，复用同一壳，补分页、标签和智能筛选契约。
4. 再完成 `新建任务 / New Task`，先补真实任务元数据契约，再连接课程/标签智能选择。
5. 每一阶段单独提供本地 route、Figma 对照图、桌面/移动截图、状态覆盖和真实/mock 边界；用户确认后进入下一页。

这样共用视觉不会在 30 多个页面里重复返工，同时用户仍能逐页看到真实页面，而不是等到所有空 route 搭完才验收。

### R1 验收门

| 阶段 | 交付 | 用户主要检查 | 通过后才做 |
|---|---|---|---|
| R1-A 共用壳 | 顶栏、选中态、模型入口、用户菜单、移动端折叠 | 是否贴近 Figma、是否删除被否定的胶囊/固定侧栏 | 工作台 |
| R1-B 工作台 | `/` 的真实统计、少量行动型任务、模型摘要 | 首屏密度、任务优先级、入口位置 | 历史任务 |
| R1-C 历史任务 | `/history` 的表格、分页、标签和筛选 | 表格信息量、标签交互、智能筛选解释 | 新建任务；用户已授权进入下一阶段 |
| R1-D 新建任务 | `/tasks/new` 的固定学期、课程和标签 | 字段、默认值、匹配/新建流程 | Q-01 添加题目；当前等待用户确认 |

## 2. R1-A 共用产品壳决策卡

### 2.1 页面工作

让教师始终知道自己在哪里，并能在一级产品区域、模型配置和账户操作之间快速切换；任务流程页另外显示任务上下文，但不恢复全局固定左侧栏。

### 2.2 固定结构

- 桌面顶栏顺序：品牌；`工作台`、`新建任务`、`历史任务`、`课程资料库`；右侧 `模型 x/y 可用`；用户名菜单。
- 当前一级入口只在文字本身使用字重和克制浅底表达；不显示 Figma 右上角独立页面状态胶囊。
- 用户名菜单固定包含：`账户设置`、`模型与 BYOK`、`退出登录`。
- 任务页在顶栏下增加轻量任务上下文栏：返回入口、任务名、当前阶段、保存状态和阶段门禁。
- 最终结果工作区可以在内容区使用局部左侧导航；其他全局页面不使用固定左栏。
- 移动端：品牌和当前页保留；一级导航折叠为菜单；模型入口和用户菜单保持可达；任务上下文可横向滚动或折叠，但不能隐藏当前阶段。

### 2.3 双语与 route

| 中文 / English | route | 备注 |
|---|---|---|
| 工作台 / Workspace | `/` | 旧 `/dashboard` 如存在只做兼容重定向。 |
| 新建任务 / New Task | `/tasks/new` | 创建成功进入现有 canonical route `/tasks/:id/upload/problems`。 |
| 历史任务 / History | `/history` | 与工作台的少量任务摘要完全分离。 |
| 课程资料库 / Course Library | `/knowledge-base` | 先保留现有 path，避免无价值的后端/链接迁移。 |
| 账户设置 / Account Settings | `/settings/account` | 旧 `/settings` 兼容重定向。 |
| 模型与 BYOK / Models & BYOK | `/settings/byok` | 旧 `/experts` 兼容重定向。 |
| 待复核结果 / Results Review | `/tasks/:id/review` | 只承载教师确认前状态。 |
| 最终结果与分析 / Results & Insights | `/tasks/:id/results` | 只承载正式结果及长期复看。 |

后续子 route 使用资源层级表达上下文，例如 `/tasks/:id/results/questions/:qid`；不把 UI tab 名称编码成后端状态，也不让同一路由根据任务状态完全替换页面。

### 2.4 复用与新增

- 复用当前登录会话、React Router、React Query、i18n provider、主题 provider 和任务阶段计算的有效部分。
- 重做当前 `AppShell` 的可见布局；旧固定左侧栏不作为兼容模式保留。
- 建立单一 route 配置源，让桌面导航、移动菜单、面包屑和选中态共享，不复制 path 判断。
- 建立完整中英文 message key；普通页面不出现 `Dashboard`、`Rate limit`、`final result` 等中英混排。
- 旧 route 在迁移期只做显式 redirect，不能维护两套页面实现。

### 2.5 状态与验收

- 覆盖已登录教师、会话加载、会话过期、模型状态加载/失败、0 个可用模型、部分可用和全部可用。
- 模型入口只展示真实可得的 provider/model、启用状态和可用数；不能伪造余额、token、费用或健康度。
- BYOK registry 完成用户 owner 隔离前，文案只能是“当前可用模型配置”，不能称为“你的 BYOK”。
- `1440x900` 对照 Figma 01–03 顶栏；另验收 `1280x800`、`390x844`、`430x932`。

### 2.6 当前决定

没有阻断实现的问题。名称和具体 route 已由用户授权主 Agent按“后端简洁、语义无冲突”原则确定；低风险图标、间距和折叠细节在 Figma 对照验收时调整。

## 3. R1-B 工作台 / Workspace 决策卡

### 3.1 Figma 与页面工作

- Figma：`01 Dashboard 任务驾驶舱`，node `1:2`。
- 唯一主要工作：教师进入系统后，在不滚动的首屏内看清“需要我做什么、什么正在运行、最近完成了什么、模型是否可用”。
- 不承担完整历史管理；完整历史只在 `/history`。

### 3.2 首屏结构

沿用 Figma 01 的标题、四个统计摘要、少量任务表、单一新建任务 CTA 和大面积留白，做以下确认后的改动：

1. 页面标题为 `工作台 / Workspace`。
2. 四个统计默认使用：`进行中`、`待我处理`、`本学期已完成`、`可复用资料`。统计必须来自真实状态；若相应后端字段未就绪，显示明确不可用状态，不编造数字。
3. 新建任务是页面唯一强调色主按钮。
4. 任务区最多显示 4 条桌面任务、窄屏最多 3 条；默认优先级为：错误/需要立即处理 > 运行中 > 待复核/待导出 > 最近更新。
5. 无未完成任务时回退显示最近 1–2 个正式完成任务，并给出查看结果或下载报告入口。
6. 任务区标题右侧放轻量 `查看全部`，进入 `/history`；顶栏仍保留独立历史任务入口。
7. 顶栏用户名左侧显示模型可用数；工作台内只展示 2–3 个真实模型摘要和异常/需配置提示，点击进入 `/settings/byok`。
8. `近期智能提醒` 最多 2–3 条，只保留能触发具体行动的内容；没有真实洞察时使用简洁空状态，不生成装饰性建议。

### 3.3 表格字段与操作

桌面字段：任务、课程/标签、阶段、进度、待处理、更新时间、下一步。移动端转成无嵌套卡片的紧凑列表。

- 点击任务名或主操作进入 `getTaskDestination` 对应真实阶段。
- 运行任务显示真实进度与 ETA；无 ETA 时不显示假时间。
- 错误行显示短错误摘要和恢复动作，技术详情折叠。
- 状态颜色最多使用主色、中性、警告和危险语义；不为每种状态发明一种彩色 pill。

### 3.4 真实数据与后端边界

当前可复用：`GET /tasks/`、任务状态/进度 helper、`GET /experts/available` 及现有 React Query hooks。

必须补齐后才能算功能完成：

- Task 的待复核、复核完成、分析生成、正式完成等状态；当前 `graded` 不能同时代表所有结果阶段。
- 一个按当前用户聚合的工作台统计契约；实现优先采用任务查询返回的结构化 summary，避免前端下载全部历史后自行统计。
- 多任务分页/limit 与行动优先排序。
- BYOK registry 按用户隔离；密钥继续只在后端内存/安全存储中处理，不回传前端。
- 课程/标签和本学期字段就绪后再显示相应统计；在此之前明确隐藏而不是放假数据。

推荐 API 保持简单：`GET /tasks/?view=workspace&limit=4` 返回 `items + summary`；`GET /tasks/` 的现有字典响应在迁移期由兼容 adapter 接收。模型状态继续使用 `/experts/available`，不复制到任务 API。

### 3.5 必验状态

- 首次使用空状态。
- 只有已完成任务。
- 超过 4 个行动型任务。
- 同时有运行、错误、待复核、待导出任务。
- 任务列表加载、失败和刷新。
- 0/部分/全部模型可用与模型 API 失败。
- 长任务名、长课程名和多标签。

### 3.6 当前决定

统计名称先按上述四项实现为 i18n 文案；真实数据不足时优先隐藏或解释，不用占位数字。首轮截图验收可调整具体统计项名称和最多显示条数，不影响数据模型。

## 4. R1-C 历史任务 / History 决策卡

### 4.1 Figma 与页面工作

- Figma：`02 History 网盘式任务列表`，node `1:85`。
- 唯一主要工作：在大量历史任务中通过结构化条件、标签或自然语言找到任务并继续处理或复看结果。

### 4.2 页面结构

1. 顶部标题和一句说明，不增加大 hero。
2. 第一行是关键词搜索和 `智能筛选` 输入；智能筛选解析后必须显示为可编辑条件 chips，而不是只返回一份不可解释的结果。
3. 第二行是学期、课程、标签、状态、`未完成`、`需要我处理` 与排序；可一键清空。
4. 主体使用 Figma 02 的网盘式表格。默认每页 25 条，支持 25/50/100；不一次渲染全部任务。
5. 表格列：任务、学期、课程、标签、当前阶段、进度/ETA、待处理、更新时间、下一步。
6. URL 保存筛选、排序和页码，打开详情后返回能恢复原位置。
7. 点击任务进入真实当前阶段；正式完成任务进入 `/tasks/:id/results`。

### 4.3 Overleaf 式标签

- 课程以不可与用户标签混淆的系统标签显示；课程可空。
- 自定义标签可从已有项选择、快速新建、重命名、换色、从单个任务移除。
- 颜色只从低饱和受限调色板选择；颜色不是筛选和识别标签的唯一方式。
- 删除标签默认只解除/删除标签定义，不删除任何任务；若标签仍关联多个任务，确认框明确显示影响数量。
- 教学班、项目组、考试类型等不建立固定字段，均可由自定义标签表达。

### 4.4 智能筛选

支持如“找出 2025-2026 秋季学期、线性代数、还没复核完的任务，按最近更新排序”。后端返回：

- 可执行的白名单字段、运算符、真实课程/标签 ID 和排序；
- 每个条件的自然语言解释；
- 无法确定的部分与候选项；
- 不允许返回或执行任意 SQL。

确定性筛选始终可用；AI 失败、限流或无 key 时仍可用普通搜索、下拉筛选和排序。

### 4.5 真实数据与后端边界

2026-07-13 History 阶段已经扩展 `GET /tasks/`：无查询参数时继续返回当前用户任务字典以兼容旧调用；带任一 History 查询参数时返回服务端分页、筛选、排序和 facets 结构。Task 已接入 `semester_id / course_id / tag_ids`，标签使用独立 owner-scoped API，并在任务写入时校验真实 owner 与 ID。

推荐保持一个列表入口：

```text
GET /tasks/?page=1&page_size=25&semester_id=...&course_id=...&tag_ids=...&statuses=...&unfinished=true&sort=updated_desc&q=...
```

响应为 `items + total + page + page_size + available_facets + facets`。智能解析使用独立、受限的 `POST /tasks/query/interpret`，只产生相同的白名单结构化查询对象；最终仍由普通 `GET /tasks/` 执行。静态 route 已在 `/{task_id}` 前注册并有路由契约测试。

当前已实现：用户隔离标签 API、标签引用计数与安全解除、任务分页/筛选/排序、确定性自然语言解释器，以及 Agent -> Skill -> Tool -> Provider 的可选 LLM 路径。

仍未完成：

- Task/Course/Tag 和查询限额均为进程内存，重启会丢失，多 worker 之间也不共享；正式环境仍需 PostgreSQL/repository 与持久限额。
- LLM 智能查询默认关闭；在补齐硬 token/provider-call 限额、多进程持久限额和用户 BYOK 隔离前，不开放共享模型自动解释。
- 后端仍没有 `finalized` 正式完成状态；`graded` 只显示为结果已生成、等待复核，不能称为正式完成。
- 后端没有可信 ETA 时表格显示 `—`，不依据状态伪造时间。

### 4.6 必验状态

- 无任务、1 条任务、数百条任务和翻页。
- 多标签、无课程、历史学期、超长名称。
- 智能筛选精确解析、歧义、无匹配、限流和无 BYOK。
- 标签新建、重复、重命名、换色、移除和删除影响确认。
- 从任务详情返回后恢复筛选、页码和滚动位置。

### 4.7 当前决定

默认页大小 25，更新时间倒序；标签删除不删除任务；AI 只解释并生成白名单查询，不自动修改标签或任务。这些默认值已按真实接口实现，可在页面验收时微调，但持久化、正式完成状态和共享模型安全门禁不能以视觉验收替代。

## 5. R1-D 新建任务 / New Task 决策卡

### 5.1 Figma 与页面工作

- Figma：`03 New Task 新建任务`，node `1:156`。
- 唯一主要工作：用最少字段创建一条真实任务，然后进入添加题目；不在本页上传文件或展开完整专家配置。

### 5.2 字段与默认值

| 字段 | 必填 | 默认与行为 |
|---|---|---|
| 任务名称 | 是 | 空白校验；不自动拿课程名替代。 |
| 学期 | 是 | 固定下拉，默认当前学期；最早 `2025-2026 秋季学期`，最晚为当前学期之后一个学期。 |
| 课程 | 否 | 可搜索、可选择、可显式新建；选择后自动关联同一课程系统标签。 |
| 标签 | 否 | 多选已有或显式新建；可表达教学班、项目组、考试类型等。 |

不提供教学班或分组字段。专家、OCR 和资料来源不作为创建任务的必填字段；本页只显示一行“使用当前模型配置”的可选摘要，配置异常时可进入 `/settings/byok`，但仍可先保存草稿。

### 5.3 学期算法

- 学年以秋季开始。
- 默认月份映射：秋季 8–11 月、冬季 12–2 月、春季 3–5 月、夏季 6–7 月。
- 12 月的冬季属于当年开始的学年；1–7 月属于上一自然年开始的学年。
- 生成从 `2025-2026 秋季学期` 到“当前学期的下一学期”的有序选项。
- 算法是产品选择器默认值，不声称等同任何学校的精确校历；映射集中为可测试配置，日后可改而不迁移已有 `semester_id`。

例如 2026 年 7 月：当前为 `2025-2026 夏季学期`，额外可选下一项 `2026-2027 秋季学期`。

### 5.4 课程/标签智能选择

输入采用逐层匹配，任何 AI 推荐都不能自动选中或自动建库：

1. 规范化后的完全匹配：直接列出真实已有项并标记 `完全匹配`。
2. 前缀、拼写、拼音等确定性模糊匹配：列在 `可能相关`。
3. 安全限额与用户级 BYOK 隔离就绪后，用户可主动请求语义候选；仍列在 `可能相关`，显示为什么推荐。
4. 找不到时显示 `新建“……”`。
5. 点击新建后，后端再次做完全、别名和相近项查重；相近时让用户选择已有项或明确 `仍然新建`。

课程和标签候选只能引用当前教师有权限访问的真实 ID；AI 不得编造 ID、静默合并或覆盖已有记录。

### 5.5 创建与错误行为

- 主按钮：`创建并添加题目 / Create & Add Problems`。
- 成功：原子写入任务元数据，进入现有 canonical route `/tasks/:id/upload/problems`。
- 部分失败：不允许出现“任务建成但标签没保存却提示成功”的状态；后端事务失败时保持表单内容并给出可重试错误。
- 重复提交：使用 idempotency key 或提交期间禁用并在后端去重，避免双击产生两个任务。
- 离开有未提交内容的页面时提示；成功后不提示。
- 模型未配置不阻止创建草稿，只在进入需要 AI 的识别步骤时执行真实门禁。

### 5.6 真实数据与后端边界

2026-07-15 New Task 阶段已补 `GET /courses/search`、`GET /tags/search`、课程/标签规范化精确复用、确定性相近候选、相近项 409 与显式 `force_create`；`POST /tasks/` 已要求非空任务名并支持 owner-scoped `Idempotency-Key`。课程/任务/标签及幂等记录仍为内存存储，重启会丢失；语义模型匹配仍保持关闭，不能把当前词法相近项写成 AI 语义能力。

推荐保持单一创建入口：

```json
POST /tasks/
{
  "name": "线性代数期中作业",
  "semester_id": "2025-2026-autumn",
  "course_id": "c_...",
  "tag_ids": ["tag_..."]
}
```

`course_id` 和 `tag_ids` 可空。课程/标签新建走各自资源 API，不把新建对象暗藏在 task create 内；这样查重、权限和错误语义更简单。课程作为系统标签是展示/筛选关系，不复制出第二条同名用户标签。

### 5.7 必验状态

- 当前日期在每个季节边界，尤其 12 月、1 月、7 月和 8 月。
