## 1. 本轮结论

### 1.1 R02 只保留一种连续复核工作区

- 不再维护“单题 / 全部题目”两种页面模式。
- `questionId` 只表示精确深链的初始题目；进入页面后始终展示当前学生的全部筛选题目。
- 左侧题号栏与 Q03、学生作答校对及正式结果详情使用同一组件语言：有标题和题数、当前项蓝底、真实状态点、独立滚动。
- 题目搜索、题号点击、正文滚动、每题上下题按钮和键盘上下键相互同步；学生左右键、相邻按钮和直选保持独立。
- 切换学生后回到页面顶部，立即显示当前姓名、学号和相邻学生，避免停留在旧学生的题目锚点。

### 1.2 一道题在一张完整知识卡中复核

每道题按固定顺序展示：

1. 题目与学生作答，浏览态渲染 LaTeX。
2. `SmarTAI 批改结果`：原始分数、完整理由、结构化步骤、置信度、专家数、合成方式和可展开专家原始结果。
3. `教师最终结果`：右上角只编辑 `x / x` 得分；补充评语位于下方独立编辑区。
4. 评分标准和保存/确认操作。

SmarTAI 理由不再用省略号截断，教师得分与评语不再并排挤压。AI 原始结果继续只读，教师覆盖层继续使用既有真实保存合同。

### 1.3 历史页全部主区域共用一个版心

问题根因不是卡片内容，而是筛选区继承页面 `max-width`，结果计数、列表/空态和分页却各自写死 `1080px`。本轮统一为：

- 页面外层继续负责最大宽度与左右留白。
- 筛选、计数、表头、任务行、空态和分页全部使用 `w-full` 继承同一版心。
- 桌面任务名称列使用 `minmax(280px, 1fr)` 吸收新增宽度，其他事实列保持稳定，避免列间距被随意拉散。
- 窄屏仍保留表格自身 `1080px` 最小内容宽度和内部横向滚动安全，不制造页面级横向溢出。

## 2. 同类界面自查

检查范围包括工作台、课程资料库、新建任务、账户设置、模型与 BYOK，以及题目、作答、批改、复核和正式结果主页面。

- 未发现另一处“同页兄弟主白框分别采用页面最大宽度与固定较小宽度”造成的明确左右边缘错位。
- 部分页面使用 `800/900/940/1100px` 居中宽度，但它们都是单一表单、单焦点进度卡或同组内容容器，左右边缘内部一致；这是控制阅读行长和匹配 Figma 锚点的设计，不应机械拉满。
- 因此本轮只修复可验证的同类问题，不以全局替换宽度类名的方式制造新的视觉回归。
