## 1. 本阶段目标

把题目识别、作答识别、执行批改、正式结果、可视化分析和报告生成中的失败状态统一为 Figma 17 的单焦点恢复卡。错误页不堆日志、不清空已填写内容，也不让教师猜测下一步；每次只突出一个最合理的恢复动作，并保留必要的次级返回路径。

## 2. 统一视觉与交互约束

- 使用白色圆角单层容器、克制的蓝/黄/红状态色和与 Figma 01–17 相同的按钮、边框、间距语言。
- 标题先说明发生了什么，正文说明资料是否保留，主按钮直接执行恢复动作。
- 技术信息默认折叠，只显示经过白名单筛选的 HTTP 状态、稳定错误代码、处理阶段、任务编号以及真实限制值。
- 不显示 API key、原始供应商异常、答案正文、文件正文、日志堆栈或任意未经筛选的后端 payload。
- 限流等待只在后端确实返回 `Retry-After` 或等价字段时显示；没有事实依据时不猜测恢复时间。

## 3. 错误到恢复动作的统一合同

| 错误类别 | 教师看到的主动作 | 状态保留与边界 |
| --- | --- | --- |
| 没有可用模型 / BYOK | 前往“模型与 BYOK” | 携带安全的 task-scoped `returnTo`，返回后保留当前资料与页面草稿 |
| 模型限流 / quota | 重新尝试 | 仅显示真实 `retry_after`；不自动循环调用模型 |
| 文件无法解析 / 过大 / 空文件 | 重新选择文件 | 保留其他已选资料；扫描件明确说明 OCR 尚未接入 |
| 资料来源过期或已变化 | 重新选择资料 | 防止旧识别结果写入新 revision，不把 stale 当普通重试 |
| workflow revision 冲突 / 已在运行 | 刷新任务状态 | 按最新阶段继续，避免重复启动模型任务 |
| 网络或后端暂不可用 | 重新尝试 | 页面输入和已上传资料不清空 |
| 其他可恢复失败 | 重新尝试 | 显示友好摘要；详细信息仍受白名单限制 |

## 4. 实现范围

- `frontend/app/src/api/client.ts`
  - 兼容字符串与对象形态的 FastAPI `detail`，提取稳定 message/code。
  - 解析 HTTP `Retry-After` 及后端等价字段，避免限流只剩“Bad Request”。
- `frontend/app/src/lib/taskActionGuards.ts`
  - 建立单一错误分类器、恢复动作类型和脱敏技术详情白名单。
  - BYOK 入口统一为 `/settings/byok`，并支持保留当前页面回链。
- `frontend/app/src/components/ui/RecoverableActionState.tsx`
  - 建立完整与 compact 两种密度的共享恢复卡；语义、样式和动作一致。
- 已接入页面：
  - 题目文件与资料上传、题目识别进度、作答识别进度、执行批改；
  - 正式结果工作区加载、可视化自然语言图表、报告索引与报告生成。
