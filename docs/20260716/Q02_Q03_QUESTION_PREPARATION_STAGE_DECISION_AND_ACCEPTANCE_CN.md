## 1. 本轮纠正的直接结论

用户截图中的 URL 是 `/tasks/:id/problems/progress`，语义上属于 **Q-02**，不是 Q-01；但旧路由错误地继续渲染 `TaskUploadPage`，把以下内容混在同一长页：

- 添加/替换题目文件；
- 识别状态；
- 题目准备覆盖率；
- 批量资料导入；
- AI 补全说明；
- 矩阵；
- 单题全部资料槽位。

这正是 reset baseline 已禁止的旧实现。本轮不继续美化旧长页，而是纠正 route ownership：

| 阶段 | canonical route | 页面唯一职责 |
|---|---|---|
| Q-01 | `/tasks/:id/upload/problems` | 选择题目来源并启动识别。 |
| Q-02 | `/tasks/:id/problems/progress` | 只显示事实进度、步骤、事件、后台运行与错误恢复。 |
| Q-03 | `/tasks/:id/questions` | 首屏矩阵、真实覆盖率、筛选、排序与精确分流。 |
| Q-04 | `/tasks/:id/questions/:qid/content` | 只校对本题题干。 |
| Q-05 | `/tasks/:id/questions/:qid/rubric` | 只编辑本题评分标准。 |
| Q-06 | `/tasks/:id/questions/:qid/answer` | 只查看/编辑本题标答。 |
| Q-07 | `/tasks/:id/questions/:qid/tests` | 只维护编程题测试样例。 |

批改后的题目分析详情不再占用准备阶段 URL，迁移为 `/tasks/:id/results/questions/:qid`，避免“题目准备详情”和“批改结果题目分析”路由冲突。

## 3. Q-03：矩阵必须是首屏主角

### 3.1 信息层级

标题与七步流程之后立即进入一个矩阵容器：

1. 顶部一条紧凑工具栏显示四项真实覆盖率：题干复核、评分标准、标答、编程题测试样例。
2. 同一工具栏提供可解释筛选与排序。
3. 下一行立即是 sticky 表头和矩阵，不再插入上传说明、大段能力说明、导入表单、AI 表单或详情卡。
4. 桌面 `1440 × 900` 默认能看到 8 行；数据更多时只让矩阵区域纵向滚动。
5. 移动端矩阵自身横向滚动；页面根节点不得横向溢出。

固定列为：

```text
题号 | 复核状态 | 题型 | 评分标准 | 标答 | 测试样例 | 操作
```

所有可操作状态均是 route-backed 链接。`缺失` 不是装饰性 pill，而是进入对应专页的入口。

### 3.2 真实状态

`ProblemInfo.review_status` 后端正式支持：

- `needs_review`：AI 识别后尚未确认；
- `edited`：教师已经修改，但尚未最终确认；
- `confirmed`：教师明确确认。

编辑题干、评分标准、标答或测试样例时，除非同一请求明确确认，否则自动进入 `edited`；Q-03 分别显示“待确认 / 已修改待确认 / 已确认”。矩阵不伪造低置信、来源、AI 生成或教师确认字段。

### 3.3 筛选与 URL 状态

当前实现使用不消耗模型额度的可解释本地规则，支持：

- 题号、题型、题干、评分标准、标答关键词；
- `缺标答`、`缺评分标准`、`编程题`、`证明题`；
- `缺失优先`；
- 多条件组合，如 `缺标答 编程题`。

`q` 与 `sort` 写入 URL；从矩阵进入详情时同时保存返回路径和筛选条件。返回 Q-03 后恢复原筛选，不把“智能”写成尚未发生的语义模型调用。

## 4. Q-04 至 Q-07：短页面边界先行

为避免 Q-03 状态链接进入 404，本轮同步建立四个独立、可用的专页边界：

- 每页只显示当前资料维度，不把题干、评分标准、标答和测试样例重新纵向铺在一起。
- 支持上一题、下一题、题目下拉选择。
- 支持题号/题型/内容及 `缺标答 / 缺评分 / 编程题 / 已确认` 等筛选。
- 支持 `单题` 与 `全部` 两种视图；`全部` 只纵向显示当前维度和当前筛选结果，不混入其他资料槽位。
- 题干、评分标准、标答和结构化测试样例均写入真实单题 API。
- 有未保存修改时，切题、切资料页、修改筛选或离开页面会出现离开确认。
- 任务已进入解析作答/批改等后续活动阶段时，本页只读，避免与后台 workflow CAS 冲突。
- 非编程题的测试样例页明确为“不适用”，不提供假编辑器。

本轮没有把 Q-08 批量资料导入或 Q-09 AI 补全塞回这些页面，也没有放死链接。Q-08/Q-09 仍按 Figma 08/09 在下一阶段实现为独立工作流；届时缺失标答/评分标准页可增加真实入口。
