## 3. 第一批代码改造原则

- [ ] 不一次性实现所有后端未有能力，先把前端体验结构立住。
- [ ] 后端未有 API 的能力，用清晰的 UI 外壳、禁用态、派生状态或 mock summary 表达，不伪装成已经真实可用。
- [ ] 优先改真实用户最容易感知的问题：页面杂、框嵌套、状态不明显、上传后无反馈、阶段不清楚。
- [ ] 保持每个任务并行互不影响的状态展示。
- [ ] 每阶段完成后跑一次轻量测试，避免最后集中爆雷。
