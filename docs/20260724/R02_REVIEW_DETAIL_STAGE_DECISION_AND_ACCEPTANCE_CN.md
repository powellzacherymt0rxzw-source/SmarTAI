## 1. 结论与页面职责

R02 已替换此前精确复核 URL 的遗留结果页回落。页面以“一个学生的全部题目”为唯一复核工作区；每道题在同一张连续题卡中完整展示题目、学生作答、SmarTAI 批改结果、教师最终结果和评分标准。精确题号深链只确定初始滚动位置，不再维护另一套单题视觉或状态。

- 复用 Figma 15 的标题、全宽作答、AI/教师双列卡和底部评分标准层级；顶部按后续确认的八步流程显示。
- 按用户明确纠正，学生导航保留在顶部独立行；题目维度改为搜索行、左侧题号栏和题卡内上下题按钮，不采用 Figma 原稿将四个切换按钮挤在同一行的方案。
- 左/右切学生，上/下切题目；输入框、文本域、选择器、按钮、链接、弹窗和可编辑内容聚焦时不截获方向键。
- 学生筛选与题目筛选分别保存到 URL 的 `student`、`question` 参数；任一维筛选、选择或清空都不改变另一维当前对象。
- 学生支持姓名、学号、低置信/待复核规则；题目支持题号、题型、题干和有限可解释语义别名，如“积分题”。下拉明确区分“完全匹配”和“相关匹配”。当前实现零 provider 调用，不冒充通用语义检索。
- R01 矩阵仍可深链到具体题目；落地后当前学生的其他题目同时保留在连续正文和左栏中，避免重复打开多套页面。

## 2. Figma 对齐与已确认偏差

实渲染中，标题和八步流程仍遵循 Figma 15 层级；学生导航与题目搜索各自独占一行。正文左侧是 `132px` 独立滚动题号栏，右侧连续题卡按“题目与作答 → SmarTAI/教师双列 → 评分标准”顺序向下展开。题目多时只有真实内容自然滚动，不再因页面模式切换重复渲染。

| Figma 15 结构 | R02 实现 |
|---|---|
| 学生、题目四个切换按钮同一行 | 学生导航独立一行；题目改为搜索、左栏和题卡上下题，三者联动 |
| 学生作答全宽卡 | 保留；当前学生的全部筛选题目连续展示 |
| AI 理由左卡 | 改名“SmarTAI 批改结果”；显示完整不可变理由、分数、置信度、专家数、合成方式和可展开专家原始结果，不做省略截断 |
| 教师最终结果右卡 | 最终得分置于右上角并以 `x / x` 呈现；只编辑得分，补充评语作为下方独立字段 |
| 评分标准底栏 | 每题保留；题卡顶部与底部操作负责滚动到上/下一题 |
| 原稿按钮与评分标准发生视觉挤压 | 保存/确认留在教师卡内部，底栏不重叠 |

彩色只用于当前步骤、复核状态和主操作。桌面没有恢复旧结果页的横向五块大 tab、固定侧栏、知识库说明或长学生列表。

## 3. 真实复核合同

新增 `PUT /tasks/{task_id}/reviews/{student_id}/{q_id}`：

1. 仅 task owner（或既有 admin 规则）可写，且任务必须已经 `graded` 并有真实 grading result。
2. 请求携带 `expected_workflow_revision`；不同内容的过期写入返回 409，避免两个标签页静默覆盖。
3. 分数必须位于 `0..max_score`；不存在的学生/题目返回 404。
4. 完全相同的重试幂等返回 `unchanged=true`，不重复增加 revision。
5. AI 原始 `score/comment` 永不覆盖；教师结果保存在 `teacher_score/teacher_comment` 覆盖层，并记录 `pending/edited/confirmed` 与确认时间。
6. 结果汇总统一消费 `teacher_score ?? score`，因此教师改分会立即影响 R01 得分率、学生总分、题目平均分和后续结果模型；AI 原始分仍可审计。
7. 当前覆盖层、Task/JobStore 与审计时间仍在进程内存，服务重启会丢失；R02 没有冒充数据库持久化、正式结果版本或任务级完成状态。

R01 的第四张指标随此合同从“已批注”升级为真实“已复核”；已确认格显示“已确认”，普通非空批注仍只显示“批注”。A00 现已补上任务级确认、结果冻结和 stale 版本，仍不能由逐格 `confirmed` 自动推断完成，必须由教师显式执行任务级确认。
