## 1. 结论

本轮没有为通过检查而继续堆页面，也没有重复生成已经存在的 Figma 双尺寸截图。当前产品已经从旧版“一个长页面承载整个阶段”拆成上传、进度、总览、详情、批量导入、AI 补全、批改、复核和正式分析等独立 route；总览只负责判断与分流，详情只处理一个学生、一道题或一种资料。

允许自然长滚动的场景只剩用户数据本身需要完整阅读的页面，例如：

- 单学生全部题目、单题全部资料的“全部查看”模式；
- 题目、学生、复核和报告的真实列表；
- 可视化报告及批量导入复核结果。

这些页面不会再把上传设置、识别进度、矩阵总览和逐项编辑同时堆在一个工作区。

## 2. 页面族审计

| 页面族 | 当前唯一主要任务 | 主分流方式 | 长内容边界 |
|---|---|---|---|
| 工作台 / 历史 | 看优先任务与统计；查找历史任务 | 顶栏和任务行入口 | 历史表格分页/筛选，不展开任务详情 |
| 新建任务 | 填写任务最小元数据并创建 | 单一创建 CTA | 无长配置页 |
| 课程资料库 | 管理资料文件与分组 | 搜索、表格、短对话框 | 仅真实文件列表 |
| 账户 / BYOK | 管理偏好；管理模型配置 | 用户菜单、短对话框 | 不展示运维或开发者状态 |
| Q01 / Q05 / Q03 | 添加题源；观察识别；判断题目资料矩阵 | 识别完成自动/明确进入矩阵 | Q03 不在矩阵下展开题目详情 |
| Q08 / Q09 | 批量导入资料；确认 AI 补全范围 | 独立进度与复核 route | 只滚动真实匹配结果 |
| Q07 | 校对单题的一个资料 section | section 路由、题目选择与上下键 | “全部查看”才自然滚动全部资料 |
| S01 / S02 / S03 | 上传作答；观察识别；判断学生 × 题目矩阵 | 独立进度和矩阵分流 | S03 不展开完整答案 |
| S04 / S05 | 查看单学生全部题目；校对单学生 × 单题 | 学生/题目两维独立导航 | S04 的全部题目为有意长视图 |
| C01 / C02 / C03 | 配置批改；批前确认；观察批改进度 | 单一阶段 CTA | 高级设置按需展开 |

| A00–A07 | 在独立子页查看总览、题目、学生、图表或下载 | 结果工作区局部导航 | 全量表格、图表和报告按真实数据滚动 |

`frontend/app/src/main.tsx` 中的 canonical 路由均指向上述独立页面；旧 `/upload/:kind`、`/setup` 和旧结果深链只做状态感知兼容跳转，不再渲染旧长页面。

## 3. 信息密度与视觉层级门禁

- 32 个 route 页面入口均有唯一页面级 `h1`；任务阶段由共用流程条表达，不再用重复页面状态胶囊。
- 可见 route/component 中没有遗留 `Card` 或 `WorkflowSection` 页面容器；使用 Figma 的单层描边、圆角矩形指标和克制留白，不恢复旧版框中框。
- 总览矩阵和关键指标优先于说明；高级能力进入子页、折叠区或短对话框。
- 主 CTA 保持少量且与当前任务一致；次级动作使用文字按钮、行入口或底部导航，不与主 CTA 争夺强调。
- 工作台在 `1280px` 已修复页面级横向溢出；既有 `1440×900` 与 `390×844` 页面证据继续作为本轮基础，不重复截图消耗额度。

## 4. 本阶段代码修正

用户界面中的实现细节已改成教师可理解的产品边界：

- BYOK 密钥说明改为“只用于模型请求，保存后不回显”，不暴露请求落在哪一层。
- 任务资料改为“试用环境资料保留说明”，不显示内存索引或服务进程实现。
- 可视化页直接说明可生成的图表和数量限制，不显示 schema、trace 或服务持久化待接。
- 人工复核信号统一称为“系统标记”，不显示实现来源。

`audit-visible-scope.mjs` 新增 `visible-developer-jargon` 门禁；以后重新出现“待后端”“前端预览”“内存索引”“backend pending”等用户可见措辞会使 lint 失败。
