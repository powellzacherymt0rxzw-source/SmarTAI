## 1. 页面决定

Figma 17 帧没有独立 BYOK 页，因此本页不复用旧长表单，而使用已经确认的同一视觉系统组合：

- Figma 09 的轻量标题、搜索/操作区和扁平表格密度；
- Figma 14 的四项大号圆角指标；
- Figma 17 的可恢复 BYOK 入口语义；
- 顶部主导航不增加 BYOK，继续从用户名菜单和模型摘要进入。

桌面首屏固定为“标题与单一添加操作 → 四项摘要 → 配置矩阵 → 官方入口”，不再纵向堆叠“已有配置卡 + 大表单卡”。添加、修改、验证和删除均在短对话框完成。

## 2. 真实状态与安全边界

- `已启用` 只表示该配置可进入任务候选，不写成在线或验证通过。
- 连通性独立显示 `尚未验证 / 验证通过 / 验证失败 / 平台托管`。
- 添加配置不会自动调用模型；验证必须再次确认，且提示会消耗一次极小 provider 请求、不会自动重试。
- 本阶段只打开并检查验证确认框，没有向真实 provider 发出测试请求。
- 修改时 key 留空由后端保留现有密钥；页面和列表都不回显 key。
- 供应商失败只展示稳定脱敏错误，不展示原始异常或 key。
- 官方链接来自后端固定 HTTPS catalog，并以新窗口打开；SmarTAI 不读取或估算余额、token、费用。
- shared/platform 配置显示为只读，不开放修改、验证或删除。

## 3. 页面与交互实现

- 四项摘要：全部配置、已启用、验证通过、需要检查。
- 桌面使用一层扁平矩阵；移动端转换为逐项短行，不把宽表强塞进页面。
- 添加对话框支持 provider、显示名称、model、key、官方 base URL、并发和 RPM。
- 编辑对话框保留 provider，允许修改其他字段；key 留空不变。
- 启用/停用即时刷新同一 React Query 状态源。
- 验证和删除使用带焦点管理、Escape 和 Tab 约束的确认对话框，不使用 `window.confirm`。
- `returnTo` 只接受同源 `/tasks/*` 路径；任务门禁进入 BYOK 后可返回原步骤。
- 顶栏模型菜单、工作台和 BYOK 页继续共同消费 `useExperts()`；顶栏文字改为“模型已启用”，不把 enabled 冒充在线可用。
- 中文和英文均为单语界面，不在同一控件混排。

## 5. 已知边界

- registry、key、验证状态和时间仍为进程内存，后端重启会丢失；本页没有把它写成持久化账户设置。
- 真正的 provider 验证需要用户持有的有效 key，会产生一次外部调用，自动验收不会代替用户执行。
- 供应商用量与余额只提供官网入口，没有接入 provider billing API。
- 当前开发服务器唯一 console error 是既有 `/favicon.ico` 404，与本页业务和布局无关。
