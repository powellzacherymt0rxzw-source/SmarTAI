# C01 批改设置阶段决定与验收记录（2026-07-20）

> 路由：`/tasks/:id/grading-setup`
>
> 本页位于“题目准备完成”与“添加学生作答”之间，只负责编辑并保存本任务的批改方案。后续 C02 `/tasks/:id/grading/preflight` 只读取同一份配置做批改前确认，不再提供第二套可编辑控件。

## 1. 本阶段目标

- 以 Figma 08 的约 `900px` 居中单列面板作为主要版式，以 Figma 12 的专家组合和评分策略层级作为信息参考，以 Figma 17 的 BYOK 可恢复门禁作为错误状态参考。
- 标题、七步流程、常用设置和主动作在 `1440×900` 首屏内可见；默认最多三个主要区域，高级设置折叠，不恢复旧长页和卡片套卡片。
- 配置必须保存到任务，刷新不丢；正式批改必须使用保存的专家子集、综合方式、资料范围和评分策略，不能只做前端状态。
- 保存设置不调用模型；浏览器验收也不调用真实模型。

## 2. 已冻结的产品决定

### 2.1 成本保守默认

- 首次进入只建议一个默认专家，不因全局启用了多个模型而自动放大调用量。
- 教师主动选择多个专家时，默认使用“置信度加权”；“主模型综合评审”明确标注会增加一次模型调用。
- 平台共享模型固定单专家、单次采样；C01 不得绕过共享池 kill switch、按用户限额或 owner 绑定。

该默认直接采用文档中推荐的低成本方案。用户已要求在效果与额度之间平衡并继续下一阶段，因此不再为推荐默认单独暂停实施；所有选项仍可在页面内明确修改。

### 2.2 本阶段只展示真实能力

本阶段真实支持：

- 精确选择一个或多个当前用户可见且已启用的模型，并指定主模型；
- 单专家、多次采样、置信度加权和主模型综合评审；
- 使用全部当前任务资料，或关闭任务资料检索；
- 严格度、部分分、评语语气与长度、评语语言、改进建议、低置信复核阈值和教师注意事项；
- 配置刷新恢复、幂等保存、并发版本冲突恢复、模型变化恢复和 BYOK 返回当前任务。

本阶段不伪装支持：

- 课程资料库分组、整库和逐文件检索范围；
- 编程测试数量、正式测试脚本或可编辑沙盒超时；
- 模型实时在线验证、供应商剩余用量或可信成本/时间估算；
- 跨进程持久数据库或对象存储。

### 2.3 页面结构

1. `批改模型`：紧凑模型选择；多模型时才显示综合方式；共享池限制直接在本区说明。
2. `任务资料范围`：只提供“全部当前任务资料 / 不使用任务资料”两个真实选项，并显示当前任务资料数量。
3. `评分方式`：首屏显示严格度、部分分和评语语气；语言、长度、建议、低置信阈值、单模型多采样和教师注意事项放入高级折叠。

底部仅保留“返回题目准备”和主动作“保存设置并添加学生作答”。C01 使用七步条的“资料”阶段，不新增会挤乱 Figma 七步结构的假步骤。

## 3. 后端合同与安全边界

### 3.1 任务配置

任务保存版本化、无密钥的 `TaskGradingSetup`：

- 有序 `selected_provider_ids` 与 `primary_provider_id`；
- `single / weighted_average / judge_agent`；
- `multi_sample_n`；
- `none / all_task_docs`；
- 严格度、部分分、评语策略、低置信阈值和教师注意事项。

任务和 job 快照只记录公开 provider id 与无密钥策略，不保存 API key；任务列表只暴露“是否已配置”，不暴露教师注意事项。

### 3.2 API

- `GET /tasks/:id/grading-setup`：只读预检，返回任务版本、已保存或建议配置、脱敏模型列表、任务资料数量与 readiness；零 provider 调用，不隐式保存。
- `PUT /tasks/:id/grading-setup`：完整替换配置并带 `expected_workflow_revision`；相同指纹重放返回 `unchanged`，不同内容的旧版本返回 `stale_revision`。
- 保存时和正式批改前都重新验证 owner、启用状态、专家数量、主模型、综合方式、多采样与共享池约束。

### 3.3 正式批改消费

- 批改只运行配置中冻结的专家子集；未选专家不得被隐式调用。
- `weighted_average` 不调用综合评审模型；`judge_agent` 使用主模型综合。
- `knowledge_scope=none` 不向 Skill 传任务检索范围；`all_task_docs` 使用当前任务范围。
- 评分策略进入四类正式 grading Skill 的 canonical system prompt；评语语言来自任务配置。
- 最终置信度低于任务阈值时，确定性写入 `requires_human_review=true` 和 `low_confidence` 原因。

## 4. Figma 对齐与明确偏差

- C01 没有独立导出帧，因此不是凭旧页面继续美化，而是使用三张相邻 Figma 的组合约束：Figma 08 决定单列密度，Figma 12 决定字段层级，Figma 17 决定无模型恢复状态。
- 删除 Figma 顶栏右侧独立阶段胶囊；全局顶栏只保留一级导航和账户/模型入口，阶段由页面内七步条表达。
- 术语统一为“资料”，减少彩色状态胶囊；颜色只用于主动作、当前步骤和必要警告。
- 不复制 Figma 12 的只读批改前确认内容；那部分留给 C02。
