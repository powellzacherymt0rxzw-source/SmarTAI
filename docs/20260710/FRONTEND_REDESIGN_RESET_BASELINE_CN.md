## 4. 教师视角下的信息架构

### 4.1 全局层

全局层只负责切换工作域，不负责展示任务内的所有阶段。

推荐顶部导航：

```text
[SmarTAI]  工作台  新建任务  历史任务  课程资料库        [模型 2/3 可用 ▾]  [用户名 ▾]
```

约束：

- [ ] 桌面端采用轻量顶部导航，摒弃当前固定宽侧栏作为默认方案。
- [ ] 一级导航不超过 5 个可见入口。
- [ ] 点击右上角用户名打开账户下拉菜单；菜单包含 `账户设置`、`模型与 BYOK` 和 `退出登录`。
- [ ] `BYOK 专家` 和 `设置` 不作为常驻顶部主导航；关键门禁发生时提供直达 `/settings/byok` 的入口，并保留返回被阻断步骤的信息。
- [ ] `退出登录` 与普通导航项用分隔线分组，执行后清理登录态并返回登录页；存在未保存编辑时先提示。
- [ ] `新建任务` 是稳定可见的主操作。
- [ ] `历史任务` 始终是独立顶部一级入口，不与 Dashboard/工作台合并；工作台负责统计、待处理任务、近期洞察和快捷入口，历史任务负责完整档案。
- [ ] 原 `任务总览` 已改名为更泛化的 `工作台 / Workspace`，避免用户误以为这里只是历史任务列表；名称进入 i18n，首个壳截图只验收视觉呈现。
- [ ] 当前页面只保留一个明确激活态：对应顶栏文字加粗，可配低饱和浅色选中底；不用额外胶囊或大面积彩色底。
- [ ] 顶栏右侧不再显示页面名或任务状态胶囊；在用户名左侧展示真实工具入口 `模型 x/y 可用`，使用状态点/文字而不是大胶囊。
- [ ] 点击 `模型 x/y 可用` 打开模型摘要，可查看 provider、模型、可用状态，并进入 BYOK 页面添加/修改 key；每个 provider 可提供官方控制台/用量页面外链。
- [ ] 移动端折叠为菜单，但任务当前阶段与主要 CTA 仍直接可见。

### 4.2 任务层

进入具体任务后，增加轻量任务上下文栏，不再让全局导航承担任务流程：

```text
< 返回工作台       算法设计第 3 次作业     当前：题目准备 3/10
题目文件  题目准备  批改配置  学生作答  批改  复核  分析与导出
```

- [ ] 已完成阶段可点击返回查看。
- [ ] 当前阶段明确但克制地突出。
- [ ] 未到阶段不可点击，悬浮或点击时给出短提示和返回当前阶段动作。
- [ ] 不在每页重复完整大段阶段说明。
- [ ] 任务名称、当前阶段和保存状态可见，避免用户忘记自己在处理哪个任务。

### 4.3 页面层

每页固定使用以下节奏：

```text
面包屑 / 返回
页面标题                         单一主操作
一句必要说明（可省略）
轻量局部导航或筛选
当前任务主体
底部上一页 / 下一步
```

页面不再默认包进一张大 Card，section 也不再逐层加框。优先使用留白、分隔线、标题层级和背景层次。

### 5.0 跨阶段 canonical task entry 纠偏（2026-07-20）

用户从工作台/历史任务点击草稿后实际进入遗留 `/tasks/:id/setup` 长页。审计确认新版 Q01 `/tasks/:id/upload/problems` 已存在，问题不是缺少新页面，而是任务卡片 destination resolver、`/tasks/:id` 静态重定向与新建任务跳转各自维护了不同入口。

本轮修复规则：

- [~] 工作台、历史任务、直接任务 URL 与所有“继续任务”动作必须共用一个状态感知 resolver；`draft` 一律进入 Q01。
- [~] `/tasks/:id` 是 canonical 兼容入口；旧 `/tasks/:id/setup` 只做同一 resolver 的兼容跳转，不再渲染遗留 `TaskSetupPage`，也不得成为任何新链接的目标。
- [~] `error` 不得被默认分支吞回 `/setup`；应根据最近失败 job/已有任务事实回到对应的新阶段恢复页，并在无法精确判断时采用最早安全可恢复阶段。
- [~] Q01 的返回动作进入 `/history`，让教师回到完整任务档案，而不是返回已退役页面。
- [~] 遗留 Setup 唯一真实且仍需保留的能力——当前任务 KB 资料上传、列表、删除——迁入独立 `/tasks/:id/materials`，由 C01 的任务资料范围区域进入并可返回 C01。

## 7. 作答流程必须怎样重做

### 7.1 添加学生作答页

只负责：上传、名单来源摘要、识别专家/OCR 摘要、覆盖风险提示和开始识别。不要同时展示校对矩阵或批改前确认。

- 自然语言筛选入口。

### 7.4 学生作答总览

- [ ] 显示学号、姓名、身份匹配状态和所有题目的识别状态。
- [ ] 可以按题目快速切换。
- [ ] 支持上一位/下一位学生，并明确显示姓名和学号。
- [ ] 身份修正是独立轻量编辑，不与所有答案编辑混在一起。

## 8. 批改配置与批改前确认必须区分

### 8.1 批改配置

位于题目准备完成后、上传学生作答前，负责可编辑的批改方案：

- 专家选择：本任务勾选一个或多个，不要求去 BYOK 页停用其他专家。
- 多专家综合方式。
- 资料范围：具体文件、分组或全部课程资料库。
- 评分策略：严格度、部分分、评语风格和必要高级项。
- 编程题默认测试样例数和沙盒超时，默认值直接显示，高级编辑折叠。

### 8.2 批改前确认

位于作答校对完成后，只做最终 preflight：

- 题目和作答是否确认。
- 是否仍有低置信或身份异常。
- 专家、资料和评分策略摘要。
- 成本/耗时估计。
- 阻断原因与直接修复入口。
- `开始批改` 唯一主按钮。

不要把批改前确认重新做成第二个配置大页。

## 9. 页面长度、层级和文案硬指标

### 9.1 页面长度

- [ ] `1440 x 900` 下，页面标题、核心内容、当前主操作都应在首屏可见。
- [ ] 上传、配置、进度、详情等标准页面目标为不超过约 `1.5` 个视口高度。
- [ ] 如果核心任务需要超过 `2` 个视口，优先拆子页面，不继续加 accordion 粉饰长页。
- [ ] 数据总览表允许纵向滚动；编辑流程不应靠长滚动完成多个不同任务。

### 9.2 信息量

- [ ] 一个决策点同时可见选项不超过 4 个；更多选项分组或收进菜单。
- [ ] 一页只有 1 个主按钮，最多 2 个直接可见次要按钮，其余放菜单。
- [ ] 一个表单组最多同时显示 4 个字段，再进入下一组或高级折叠。
- [ ] 每个页面最多 3 个主要内容区。

### 9.3 框与卡片

- [ ] 卡片嵌套深度为 0 或 1，禁止 Card 内继续套 Card。
- [ ] 页面主体默认无外层大 Card。
- [ ] section 优先用留白、分隔线和标题区分。
- [ ] 卡片只用于真正独立、重复、可选择的对象，或错误/确认等特殊状态。
- [ ] 不把每一段文案、每一个状态和每一个表单都包框。

### 9.4 文案

- [ ] 页面标题下的说明最多 1 句，能删则删。
- [ ] 普通 inline help 最多 2 行，复杂说明放 tooltip、帮助抽屉或“了解详情”。
- [ ] 按钮直接描述结果，例如“开始识别题目”“保存评分标准”，不用“提交”“确认”这类模糊词。
- [ ] 不向教师显示“后端待接”“前端推断”“字段未返回”等开发术语。
- [ ] 后端未完成的功能通过 feature flag 隐藏，或在设计 review fixture 中展示，不在生产 UI 堆禁用占位。
- [ ] 中文界面只显示中文，英文界面只显示英文；所有文案进入 i18n。

### 9.5 状态和色彩

- [ ] 填充色 pill 只用于当前阶段、危险、成功或需要立即处理的状态。
- [ ] 普通状态使用状态点、图标、轻量文字色或弱边框。
- [ ] 主色只用于主操作、当前选择和关键进度，不用于装饰所有框。
- [ ] 最终美工阶段负责色值、插图、品牌资产和微动效细化，不再改变信息架构和路由。

- [ ] 一个 route 同时渲染上传、进度、总览、详情和下一阶段确认。
- [ ] 单个页面组件因混合多个阶段增长到数百甚至上千行。

- [ ] 用大段说明解释产品怎么用或后端为什么没做。
- [ ] 关键动作藏在页面底部，需要滚过多个屏幕才能找到。
- [ ] 总览表下方继续展开被选对象的完整详情。
- [ ] 未来阶段可以提前进入并看到一堆禁用按钮。
- [ ] 页面只通过 typecheck、build 或 HTTP 200 就宣称完成。
- [ ] 没有逐帧对照 Figma 就宣称“参考 Figma”。
- [ ] 用现有组件方便复用作为改变设计的理由。

## 13. 下一轮必须使用的工具与协作方式

### 13.1 工具顺序

1. `figma` / `figma-use`：读取准确 frame、结构、截图和设计变量。
2. `impeccable:shape`：每一批页面先明确用户任务、页面边界、关键状态和反目标。
3. `frontend-design`：建立 SmarTAI 专属、克制但有识别度的产品视觉方向。
4. `figma-implement-design` 或设计到代码流程：逐帧实现，不凭文字想象。
5. `react-best-practices`：拆 route、view model 和组件，避免再次出现超大页面。
6. `frontend-testing-debugging`、浏览器控制或 Playwright：真实点击、截图和响应式验证。
7. `impeccable:critique` / `impeccable:distill` / `impeccable:harden`：分别检查层级、删减和错误/i18n/边界状态。

### 13.2 多 Agent 建议分工

- Agent A：Figma 逐帧读取、页面清单和视觉差异审计，只读设计与截图。
- Agent B：全局导航、任务上下文栏、设计 token 和基础组件。
- Agent C：题目上传、进度、总览和单题子页面。
- Agent D：作答上传、进度、矩阵、学生与单份作答页面。
- Agent E：批改配置、批改进度、结果复核、分析导出。
- 主 Agent：路由架构、业务逻辑抽取、合并、阶段测试、截图对比和清单更新。

所有写代码 Agent 必须使用不重叠文件范围，并被明确告知不能恢复或覆盖其他 Agent 的改动。

### 13.3 每个页面动工前必须先过“页面决策卡”

每开始一个新 route，主 Agent 必须先向用户提供一张简短决策卡，内容固定为：

1. 对应的 Figma frame/node，以及必须保持的视觉结构。
2. 旧对话和旧文档已经确定的功能、状态与数据边界。
3. 本页将复用的真实 API，以及必须新增的后端能力。
4. 仍未确定且会影响用户体验或数据模型的细节。
5. 主 Agent 的推荐方案、理由，以及最多 1 至 3 个必须由用户确认的问题。

- [ ] 未确认的问题如果只影响微小文案、图标或低风险视觉细节，可以按 Figma 和设计系统默认值继续，并在验收时标注。
- [ ] 未确认的问题如果影响字段含义、实体关系、默认操作、数据写入、付费调用、删除/覆盖或流程切分，确认前不得实现该页面。
- [ ] 页面实现后必须交付 Figma 对照截图、功能/状态清单、响应式截图、真实与 mock 数据边界及偏差说明。
- [ ] 用户确认当前页面后，才进入该批的下一个新页面；共用壳、token、类型和无争议基础组件可以并行准备。

## 17. 与后端的边界

- 有 API 的能力接真实数据。

## 18. 最终判断标准

教师不是来学习 SmarTAI 的系统结构，而是来完成一次批改任务。好的页面应该让产品退到后台，让题目、学生、进度和下一步变得清楚。

下一版前端的目标不是“功能都能找到”，而是：

1. 当前需要的功能马上找到。
2. 当前不需要的功能不会干扰。
3. 每一步完成后自然进入下一步。
4. 出错后知道发生了什么、会不会丢数据、现在能做什么。
5. 页面看起来像同一个经过认真设计的成熟产品，而不是许多组件临时拼在一起。

## 20. 2026-07-11 最新结构化覆盖规则

### 20.1 学期、课程与标签

- 学期改成系统固定选项，不允许自由输入；格式为 `20xx-20xx 春/夏/秋/冬季学期`。
- 选项最早固定为 `2025-2026 秋季学期`，并始终允许选择当前学期之后一个学期；当前 2026 年 7 月时最多显示 `2026-2027 秋季学期`。
- 课程保留但可空；教学班和分组不再作为固定字段。
- 历史任务允许 Overleaf 式标签；课程填写后成为系统标签，教学班等需求由自定义标签表达。
- 历史页同时支持标签、学期、课程、任务状态、未完成/需处理等结构化筛选和自然语言筛选。

### 20.2 工作台、顶栏和模型信息

- `历史任务` 是独立顶部入口，与 Dashboard/工作台不同。
- Dashboard 更接近综合工作台：保留 Figma 01 的统计计数、少量待处理任务、近期洞察、模型/BYOK 摘要和新建任务入口。
- `任务总览` 名称过窄，已确认中文主名称为 `工作台`、英文名称为 `Workspace`；所有名称进入 i18n，后续可低成本调整。
- 用户名左侧提供 `模型 x/y 可用` 入口；点击后查看可用模型并进入 BYOK 添加/修改 key。
- provider 项提供其官方模型官网/控制台/用量页面外链；没有真实接口时不伪造用量数字。

### 20.3 添加题目来源

- Figma 04 除上传文件外，也可以从课程资料库选择题目来源。

### 20.4 学生/题目复核详情导航

- Figma 15 的“上一位/下一位/上一题/下一题”四个按钮不能继续挤在同一位置。
- 学生导航和题目导航在空间与状态上独立：左右切学生，上下切题目。
- 两维均支持下拉/局部侧栏、关键词、模糊和自然语言查找；例如学号/姓名或“积分题”。
- 筛选一维不得改变另一维当前选择；多个匹配项可列表展示并可分别清空筛选。

- 页面显示键盘提示；输入框、文本域、下拉和弹窗聚焦时不得拦截方向键。
