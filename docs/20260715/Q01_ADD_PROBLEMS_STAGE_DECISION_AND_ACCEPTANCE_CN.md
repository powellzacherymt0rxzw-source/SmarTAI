## 1. 本阶段唯一目标

教师为一个已创建的任务选择真实题目来源，明确来源结构，确认必要的识别前信息，然后启动题目识别。

本页只负责：

1. 上传一个真实题目文件，或从当前教师的真实课程资料库选择一个真实文件；当前课程/未分类与本人全部是检索范围，不冒充多文件来源。
2. 选择 `已按题整理`（`organized`）或 `从原文提取`（`extract_from_source`）。
3. 在从原文提取模式下填写章节、题号、页码或自然语言线索，并在正式识别前查看候选摘要、确认歧义项。
4. 查看当前教师可见的真实、已配置且已启用的模型摘要和 OCR 能力边界；该摘要不冒充实时连通性验证。
5. 通过唯一主要操作启动识别，随后立即进入独立题目识别进度页。

本页不展示题目识别日志、题目准备总览、单题编辑、评分标准、标答、测试样例、学生作答或批改配置。

- `organized` 是保守默认，默认态尽量保持上述 Figma 锚点和 `1440 × 900` 首屏节奏。

- 选择 `extract_from_source` 后，说明输入和候选确认使用纵向流式增高；允许页面纵向滚动，但不得造成横向溢出、内容遮挡或固定高度重叠。

## 4. 真实来源与数据规则

### 4.1 上传文件

- 本阶段只接受后端真实可解析的文本型 `PDF`、`TXT` 和 `Markdown`。
- 扫描 PDF、图片、DOCX 和 OCR 不在本阶段实现；文件选择器、格式说明和错误提示都不能宣称支持这些格式。
- 上传区支持点击和拖拽；选中后展示真实文件名、大小和来源状态。
- **上传后加入课程资料库默认关闭**，不得因为选择文件就产生隐式资料库写入。
- 教师主动开启加入资料库时：任务有课程则归入当前课程；任务没有课程则归入该教师的“未分类”。

### 4.2 课程资料库

- 课程资料库选择必须来自 owner-scoped 后端数据，不使用 localStorage 文件名清单、硬编码样例或只存在于浏览器的假引用。
- 默认优先显示当前任务课程的资料；无课程任务默认显示该教师的“未分类”；教师可以显式切换查看全部本人资料。
- 本阶段支持选择一个具体文件，并以稳定 `material_id` 启动预检；“当前课程/未分类”和“本人全部”仅控制真实列表检索范围，不表示把所有结果合并为一个来源。
- 命名资料分组、勾选多个文件或“全部当前结果作为联合来源”依赖 G-04 的稳定集合对象、大小配额和版本语义，本阶段明确不实现，也不显示无效入口。
- 其他教师的资料、分组和内容不得出现在搜索、选择或启动请求中。

### 4.3 当前存储边界

- 本阶段的课程资料文件、来源引用、预检结果和幂等记录仍可使用进程内存实现，但必须是真实服务端资源与 owner 校验。
- 服务重启后上述数据可能丢失；当前不宣称已有 PostgreSQL、对象存储、跨进程一致性或跨资源数据库事务。
- 页面不得用“已永久保存”“云端长期可用”等文案掩盖这一边界。

## 5. 来源结构与候选确认

### 5.1 `organized`

- 默认选择。
- 表示来源只包含本次任务题目，或题号已经清楚分段。
- 系统正式识别时负责题号匹配、格式清理和低置信提示。

### 5.2 `extract_from_source`

- 用于教材章节、整章练习、长讲义或混合文档。
- 显示一个清楚的说明输入区，可填写章节、题号、页码、题目范围与自然语言线索。
- 前端与后端保存结构化模式和原始说明，不能只把模式作为视觉状态。

### 5.3 本阶段的保守预检策略

- 输入、粘贴、逐键编辑和防抖查询都**不调用模型**。
- 预检优先使用确定性文本/题号解析，形成 `已匹配 / 可能匹配 / 未找到` 候选摘要和可解释原因；候选为歧义时必须由教师确认。
- 正式点击“开始识别题目”后，才允许已配置的真实 AI provider 解释自然语言提示并执行正式识别。
- 因而本阶段不声称“AI 在输入时即时理解”，也不为预检动画或装饰性推荐消耗模型额度。
- 来源、模式、规范化说明和确认候选共同进入幂等判定；相同请求返回 `already_running` 或 `already_done`，不能重复启动后台识别。

## 6. BYOK、模型与 OCR 真实边界

- 选择来源、编辑说明和确定性预检不要求模型调用。
- 正式识别必须使用当前教师可见的 provider；没有已配置且已启用的 BYOK/共享回退模型时主按钮禁用，页面就地说明原因，并提供带返回上下文的 `/settings/byok` 入口。
- 识别摘要只展示真实 owner-scoped “已配置且已启用” provider/model；当前 `/experts/available` 尚未执行 key/模型实时连通性验证，因此不把 `enabled` 写成“已验证在线”。正式调用失败时进入脱敏可恢复错误。
- OCR 摘要明确显示“关闭 / 当前不支持”；不得把未实现能力渲染成可切换但无效果的开关。
- DOCX、图片与手写 OCR 需要后续真正的解析/OCR provider abstraction；本阶段不使用前端假开关或仅改扩展名来冒充支持。
- 不展示无法从官方接口取得的余额、token 或费用数字。

## 8. 节约额度但不降低质量的工作方式

1. 直接使用本地 Figma PNG 和已提取 token/坐标，不重复消耗 Figma MCP 额度。
2. 先锁定坐标、字段、状态机与 API 契约，再做一次实现；不靠反复截图试错寻找布局。
3. 先跑确定性契约测试、lint、typecheck 和 build，只在通过后做浏览器验收。
4. 浏览器证据控制为一个 `1440 × 900` 默认态、一个 `390 × 844` 关键态和一轮真实教师主流程；仅在发现明确偏差时补截图。
5. 输入与预检不调用模型；只有教师显式启动正式识别时才允许 provider 调用。
6. 可交给用户的低成本人工检查仅限主观文案与视觉偏好，例如长文件名、较多资料候选和中英文文案观感；坐标、溢出、owner 隔离、幂等和路由必须由代码与自动测试负责，不能转嫁给用户。
